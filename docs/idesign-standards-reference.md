# IDesign Standards Reference

This project template references IDesign standards as external guidance for architecture and implementation quality.

## Official Standards Links

- IDesign Standards landing page: https://www.idesign.net/Resources/Standards
- IDesign Design Standard (download): https://www.idesign.net/Resources/Downloads/GetDownload/2100
- IDesign C# Coding Standard (download): https://www.idesign.net/Resources/Downloads/GetDownload/1985
- IDesign WCF Coding Standard (download): https://www.idesign.net/Resources/Downloads/GetDownload/1987

## Usage Policy in This Template

- Use the official standards as reference material when defining project rules.
- Do not copy or redistribute proprietary standard content into this repository.
- Capture project-specific interpretations as internal rules, checklists, and acceptance criteria.
- Keep traceability from each adopted rule to the phase artifact where it is enforced.

## Suggested Mapping to MM-AI Phases

- Phase 3 (Architecture): apply design-standard checks to service boundaries, contracts, and call graph integrity.
- Phase 4 (Project Design): convert selected standards into explicit activities and quality gates.
- Phase 5 (Implementation): enforce coding standards through reviews and automated checks where possible.
- Phase 6 (QA): verify standards compliance through test evidence and defect classification.

## Standards Adoption Checklist

- [ ] Selected standards documented for the project.
- [ ] Project-specific rule subset defined (what is mandatory vs advisory).
- [ ] Rule ownership assigned (architect, reviewer, CI policy).
- [ ] Compliance evidence path defined (reports, checklists, gate artifacts).
- [ ] Exceptions process documented with expiry and approver.
